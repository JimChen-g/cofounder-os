# T11–T16 bounded execution

The September founder authorization extends the accepted T07–T10 baseline with a
single supported engineering task: material manifest completeness. This is separate
from the historical insurance demo's planning-only task. The original
WorkflowController remains the sole lifecycle authority. No T17 delivery approval
or T26 mobile approval is claimed.

## Execution

`POST /api/engineering/runs` accepts a stable `request_id` and the fixed task
`materials_completeness`; `GET /api/engineering/runs/{id}` reads the same controller.
Authentication binds the founder or paired Feishu identity. Bridge commands are
`创建 材料检查` and `查询 <Run UUID>`. Durable dispatch provides at-most-once task
creation; interrupted runs fail/cancel rather than being silently replayed. Calls
serialize in the single API process. Existing inbox, receipts and budgets persist.

Each task has at most two Controller attempts. Each attempt owns a detached Git
worktree at its recorded base SHA, two allowed new files, 600 seconds, and retained
evidence. The entire run has four model invocation reservations and 1,200 seconds;
all requests remain restricted/local. Implementation and review use distinct
message arrays and session IDs. The model supplies file contents; the application
validates paths and creates the actual diff. A JSON Markdown fence and trailing commas outside string literals may be
normalized and are recorded; generated source strings are unchanged. Other malformed
JSON and unauthorized output fields remain rejected.
Tests and blocking review findings prevent the task output from being registered.
Passing means checks completed; it is not approval to deliver the patch.

## Sandbox and evidence

Only fixed test argv are accepted. Docker runs with no network, no capabilities,
no-new-privileges, nonroot UID, read-only source, a 64MiB temporary directory,
512MiB memory/no extra swap, one CPU and 64 PIDs. No home/configuration, Docker
socket or credentials are mounted. stdout is bounded to 100KB; timeout, output
limit and cancellation stop the named application container. Container logs are
disabled. Frozen T01 inputs are passed to the candidate; expected outputs stay in
the parent. The parent checks all 14 observations and unchanged inputs. Pytest
requires a normal nonempty pass summary. Image ID, argv, exit status, log, time,
base and patch hash are retained. A test failure is distinct from a process failure.

Task, execution and review records also use the unchanged frozen T02 envelope.
Each candidate is recorded with a real Git commit whose parent is the base; its
40-character commit is distinct from the 64-character diff digest. Tests and
review envelopes bind that commit, and the frozen material-case file supplies
the acceptance-contract digest. Envelope validation precedes successful output
registration. These records do not grant delivery approval.

Workspace cleanup is explicit and only accepts this application's inactive,
terminal workspace, after preserving diff and evidence. Failed workspaces are
retained by default. The main checkout is never mounted writable or used for
candidate execution. This is a bounded application executor, not a general shell
Agent or a guarantee against kernel/container-runtime vulnerabilities.

## Sampling

`app.evaluation.sampling.sample_task` serially runs legal local/Step candidates.
Only pre-call features are retained, with source and family/group IDs. A strict
independent JSON/semantic scorer supplies labels, with raw candidate text and
provider usage. Step Plan Credit cost remains unknown rather than inferred from
tokens. Initial observations are smoke/collection-only; no trained model, 150-item
dataset or final holdout result is claimed.
