The founder authorized this stage against 0dbf5e1 under September plan v3 and
checklist v2. July paths and deployment assumptions remain historical; the
September checkout and fixed production target from the handoff are authoritative.
No infrastructure replacement, T23 training, T26 phone approvals, or official
certification is implied by these changes.

The WorkflowController's engineering delivery extension stores current version,
approval nonce, immutable artifact checksum, decisions, feedback and idempotency
receipts in one locked atomic Run record. Checks now end at waiting_approval.
Authenticated engineering approve/reject/feedback/cancel/export routes require
the displayed base SHA, diff SHA256, revision and approval nonce. The old generic
Run write routes reject engineering mutations. Bridge remains create/query only.
Exports reverify the approved artifact and exact diff checksum.

Feedback addresses the original artifact/path/line and resumes the same Run and
Task. New candidate files are generated in a fresh isolated workspace at the
original base, tested and independently reviewed. Prior versions are retained.
Task attempt_count is never reset: the frozen total of 2 attempts takes precedence
over the separate maximum of 2 feedback rounds. No-progress, cancellation,
interruption, invalid output, test failure and exhausted limits remain terminal.
Restart does not automatically replay a durable repair intent. The Web review
page is `/ui/engineering`; credentials remain only in page memory.

The standalone `skills/spark-decide` calls `/v1/spark-decide`. It uses the fixed
Qwen short-label path, filters legal candidates before inference and never
expands per-call permissions. Missing complete interpretable candidate scores
are `null/unavailable`. This is not learned or calibrated routing.

with a disclosed 126-instance gap to the approximate 150 goal. Final holdout

`evaluation/t22` is explicitly a supplementary bounded paired runner; official
SkillEvaluator compatibility outcomes are reported separately. Neither a local

## Engineering retry correction

Real validation exposed a retry regression: an ordering defect was corrected by
regenerating both files, but the regenerated test fixtures introduced invalid
abbreviated material IDs. Failed-check retries now propose a bounded set of
exact substring edits against the previous immutable candidate; unchanged file
contents survive byte for byte. Unknown paths, missing or ambiguous anchors and
oversized edit sets fail closed. Human feedback remains restricted to its
version-bound file. Both paths retain the original Task attempt and Run budgets.
The initial instruction now spells out canonical result ordering and constructing
invalid-input tests from valid full-ID fixtures. Reviewer input carries the diff,
contract and decisive test summaries without redundant container metadata.

A subsequent real run exposed incomplete repair evidence: stopping after the
first failed gate hid a separate generated-fixture defect. The executor now
collects all three bounded gate outcomes before rejecting a candidate, stopping
immediately on timeout. Review and approval remain unreachable if any gate fails.

Reviewer presentation uses the immutable candidate's original source with file
paths and line numbers, alongside separate version/test metadata. This avoids
nested JSON escaping of code while preserving the canonical diff and digest as
host evidence. Blocking findings must identify a concrete failing input and
trace it against the shown code; the host does not override a rejected review.
