## Constraint authority

`ChatRequest` defaults to restricted/local-only. A public Step request needs an
explicit provider allowlist, cloud permission and positive cloud-call budget.
Explicit `cofounder-qwen` cannot fall back to Step. `cofounder-auto` can fall back
only within the intersection of hard grants. Nested constraints cannot override
stricter top-level constraints. `ProviderRegistry` checks permission and reserves
budget before every network attempt, including fallback; transport errors are
sanitized. Candidate ordering never grants authority.

`CreateRunRequest.constraints` carries a frozen policy. The authenticated API
creates a durable budget before planning; the Executive stores its server-generated
budget ID with the Run. Retry/resume reuses that ledger. SQLite transactions make
reservations atomic across concurrent requests and process restarts. Failed and
ambiguous calls retain reservations. The shared context follows asynchronous work
and repair requests. Legacy Runs without a ledger default to restricted/local-only.

Token accounting deliberately reserves UTF-8 byte length plus framing and maximum
output, including potential fallback attempts; it can reject early and does not
pretend to be exact billing. Cloud-call count is a hard quota, not a USD/Credit
estimate. API usage and Step Plan consumption must be reported separately. No
automatic recharge or pay-as-you-go fallback exists in the deployment recipe.
The initial default of two attempts is intentionally small; callers must explicitly
supply a suitable authorized budget for later multi-agent workflows.

## Identity boundary

The deployed ASGI app fails closed when Product/Gateway tokens are absent. Product
founder and Gateway tokens are independent. Run reads, events, artifacts, retry
and approval check the authenticated founder's ownership; body `owner` or
`decided_by` cannot impersonate another principal. Bridge token is bound to the
paired app, tenant and open_id and can access only receipt/health routes. It cannot
create, query or approve Runs in this stage. T16/T26 must extend that grant through
the same Controller, not through a second task state machine.

The original pairing had no tenant field and the app lacked historical-message
read permissions. The tenant was frozen from a new authentic SDK event only after
matching the already-paired app/open_id and p2p user message. It persists in the
0600 identity file and is reloaded on restart. No additional API scope was granted.

## Bridge reliability

Only the SDK-verified WSS callback reaches `validate_event`. It verifies identity,
message kind and size, durably inserts the inbox, then returns. The pinned SDK sends
200 after callback return and 500 when persistence throws. Slow HTTP and reply work
runs in a separate worker. Dedup key is tenant/app/message_id; event ID is audit
metadata. Changed payload under the same message key is rejected. A file lock
prevents concurrent instances. An interrupted claimed message becomes `uncertain`
and is never automatically re-consumed. The receipt API is separately idempotent.

A stable UUID is reused for at most one transport retry of the reply. A successful
platform response is recorded separately from receipt storage, service receipt,
Agent consumption and read state. This receipt worker never records an Agent
consumption, Run completion, approval or read event. The official SDK manages WSS
reconnect; SIGUSR1 is an explicit test-only disconnect trigger. The production
recipe uses one process; invoke stop before starting a different host instance.
